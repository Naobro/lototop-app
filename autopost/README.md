# 自動投稿の計算ルール

平日21時（JST）開始。02:20と06:20にも再試行する。GitHubの起動遅延はあり得る。
対象日は各実行の開始時に固定し、21時前は前営業日の結果を処理する。
当選情報が不足した場合や条件を満たす予想が不足した場合は公開を止める。

## ロト

本数字を昇順にし、最新24回の23遷移を位置別に集計する。
位は1=1〜9、10=10〜19、20=20〜29、30=30以上。
最新位置の位と同じ起点の遷移だけを分母とし、次の位の比率を求める。
各位置の比率の積を候補パターンの相対スコアとして、昇順・各位最大3個の構成を列挙する。
スコアは当選確率ではない。条件を満たす2口が作れる上位5構成を採用する。
起点の標本が0件なら頻度順で補わず、生成を停止する。

候補数字・1軍2軍は既存サイトのstats.jsを同梱した版で計算する。
ミニロト20個、ロト6 30個、ロト7 27個。SABは24回の出現5回以上=S、3〜4回=A、0〜2回=B。
共通条件：引っ張り最大2個、3連続以上禁止、同末尾1ペアまで・同末尾3個禁止、10回以上未出現最大2個、同位4個禁止。
S/Aとも5個未満・B最大1個。ロト6 ZONEは1〜13/14〜28/29〜43で、3-2-1、1-3-2、2-1-3。
ZONEと位パターンは別。9口の旧固定候補・特別指定数字は日々の最新予想に流用しない。
各パターンに2口を割り当て、出現回数・合計の中心からの距離で順位付けし、既採用数字の反復に減点して分散する。
合計値に新たなハード上限は置かない。引っ張り・連続・末尾・未出現回数・合計・ZONE・SABを各口に表示する。

## ナンバーズ

修正版numbers-stats.jsを同梱。S+2、A+1、前回数字を含む場合は24回の引っ張り率を加点、
同じ桁の前回数字から風車盤の両隣・+2・裏数字に該当すると+1。同点は頻度、数字順。
風車盤は0,7,4,1,8,5,2,9,6,3。固定の出現間隔スコアは使わない。

TOP5から候補を列挙し、スコア合計を基本に既採用の同桁数字へ0.5ずつ減点して10口を分散選択する。
N3は下2桁のミニ10口（重複ペアなし、00等は許可）。
N4はセット10口（BOX重複なし、3個同数字・ダブルダブル・直近24回と同じBOXは除外）。
購入は各200円。N4は順序一致でセットストレート金額、順不同一致でセットボックス金額を使う。
ニアは3桁の位置一致、または多重集合の3数字一致で表示するが収入に含めない。

## 保存と収支

forecasts.jsonは抽選日ごとの10口を保存し、note公開後にpublishedを付ける。
検証は公開された10口だけを使用し、当時の予想を再計算しない。
ledger.jsonは抽選日:種別をキーに上書き集計して再実行の二重計上を防ぐ。
10月2日のユーザー提供・公開済み予想を開始記録とする。以前の未記録日は0円として埋めない。
月間は記録済み分のみ。回収率=当選金額合計/購入金額合計*100。
予想・収支は公開前にGitHub保存。固定画像を使用し、タイトルは次の平日抽選の日付・種別にする。
noteの公開済みタイトルと投稿記録の両方で重複を確認する。
